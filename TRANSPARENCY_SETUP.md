# Transparency Board Firebase setup

The application uses `transparencyPosts` in Firestore and `transparency/{postId}/attachment` in Firebase Storage. Enable Storage for the existing Firebase project before uploading files. The existing staff role is `users/{uid}.role == 'admin'`.

Merge the following match block into your existing Firestore rules inside `/databases/{database}/documents`. Do not replace unrelated rules. Ensure no broader wildcard grants residents write access to these records. Protect `users` rules so residents cannot set or change their own role to admin; staff roles must be assigned by a trusted administrator.

```text
match /transparencyPosts/{postId} {
  function staff() {
    return request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
  }
  allow read: if request.auth != null;
  allow create: if staff()
    && request.resource.data.keys().hasOnly(['title', 'category', 'description', 'publishedBy', 'publishedByUid', 'createdAt', 'attachmentName', 'attachmentPath'])
    && request.resource.data.title is string
    && request.resource.data.title.size() > 0 && request.resource.data.title.size() <= 150
    && request.resource.data.description is string
    && request.resource.data.description.size() > 0 && request.resource.data.description.size() <= 10000
    && request.resource.data.category in ['Budget & Finances', 'Projects', 'Procurement', 'Reports', 'Other']
    && request.resource.data.publishedBy is string
    && request.resource.data.publishedByUid == request.auth.uid
    && request.resource.data.createdAt == request.time
    && request.resource.data.attachmentName is string
    && (request.resource.data.attachmentPath == '' || request.resource.data.attachmentPath == 'transparency/' + postId + '/attachment');
  allow delete: if staff();
  allow update: if false;
}
```

Merge this match block inside your Storage rules `/b/{bucket}/o`. The Firebase console may request permission for Storage rules to access Firestore; grant that service access when prompted. Ensure broader Storage rules do not grant resident writes.

```text
match /transparency/{postId}/attachment {
  function staff() {
    return request.auth != null && firestore.get(/databases/(default)/documents/users/$(request.auth.uid)).data.role == 'admin';
  }
  allow read: if request.auth != null;
  allow create: if staff() && request.resource.size <= 10 * 1024 * 1024
    && request.resource.contentType in ['application/pdf', 'image/jpeg', 'image/png'];
  allow delete: if staff();
  allow update: if false;
}
```

These rules are provided for merging; they have not been deployed. Download links generated by Firebase are shareable bearer links, so publish only documents intended for public transparency.

Verification with separate staff and resident accounts:
- Staff can publish a text-only post, publish with a PDF/image, and remove a post.
- Residents see posts and can open attachments, but have no publishing controls.
- Direct resident Firestore create/delete and Storage upload attempts must be denied by the deployed rules.
- An unsupported file or a file over 10 MB is rejected. Failed uploads preserve form details.
- Search/category filters work and empty/loading/error states are shown.

## Deployable rule files now included

The repository now includes `firestore.rules`, `storage.rules`, and `firebase.json` covering the current users, requests, and Transparency Board collections. Compare them with your live rules before deployment; deployment replaces the live rules and unrelated collections are denied unless added explicitly.

To enable live uploads:
1. In Firebase Console, open project `antonino-cf44b` > Storage. Complete setup if no bucket exists and resolve any billing requirement shown by Firebase. Confirm the bucket is `antonino-cf44b.firebasestorage.app`, matching `src/firebase/config.ts`.
2. Verify your signed-in account has `users/{UID}.role` set to `admin`.
3. Copy `firestore.rules` into Firestore Database > Rules and publish after merging any unrelated existing rules.
4. Copy `storage.rules` into Storage > Rules and publish after merging any unrelated existing rules. Approve the Firebase service permission prompt for reading Firestore roles if shown.
5. Refresh the app, sign in as staff, and publish a small PDF/JPG/PNG. Check it appears in the resident board and opens correctly.

Alternatively, with Firebase CLI installed and authenticated, deploy reviewed rules from this directory:

```powershell
firebase deploy --only firestore:rules,storage --project antonino-cf44b
```

The app now reports progress, supports canceling file transfer, rejects empty/unsupported/oversized files, and distinguishes permission, bucket, quota, and connection failures. Publishing begins only after the attachment finishes uploading. Text-only publishing does not need Storage.

No live Firebase rules were deployed by the coding agent. Unit tests mock Firebase and do not prove live project permissions or bucket configuration.

## Direct Firestore images (current behavior)

New JPG/PNG uploads are now saved as base64 data URLs in the `imageData` field of the `transparencyPosts` document. These image uploads do not call Firebase Storage. The board displays the stored image directly, and deleting its post also deletes the image data. Existing Storage attachments still open normally; no existing files are migrated automatically.

Images must be 600 KB or smaller. Larger images are rejected with instructions to resize them. This leaves room for base64 encoding and post fields under Firestore's 1 MiB document limit. PDFs remain in Firebase Storage with the existing 10 MB limit.

Before publishing new images, merge the updated `/transparencyPosts/{postId}` block from `firestore.rules` into your live Firestore rules. It allows and validates `imageData`; the older allowlist in this guide will reject the new field. Preserve your current staff/request rules when merging.

Deploy the imageData single-field index exemption from `firestore.indexes.json` too (merge existing index definitions before deploying). Image data is for display, not searching. Each board document read includes its image data.

```powershell
firebase deploy --only firestore:rules,firestore:indexes --project antonino-cf44b
```

These changes are local only; live rules and index settings have not been deployed.
